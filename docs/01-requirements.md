# 用户、目标、范围与成功标准

题号 1，素材审核与发布排期 Agent。用户是内容编辑和审核人员，目标是把素材 ID、元数据、时间要求、规则及现有排期转为无冲突、可确认的排期草稿。

## 范围

- 读取本地合成素材；补查缺失字段；执行规则检查；查询候选时段；保存 SQLite 草稿。
- 模型根据工具结果选择下一个动作；工具层独立执行权限与业务校验。
- 输出每项素材审核状态、风险、建议时段、待确认项及草稿保存结果。
- 仅草稿，绝不接入真实发布。硬性时间变更必须保留待确认状态，不能自行视为批准。

## 验收标准

| 场景 | 可观察成功标准 |
|---|---|
| 正常 | 审核通过、原时间可用、草稿真实写入、未发布 |
| 信息不足 | 模型选择补查；仍不足则请求补充，不保存 |
| 规则风险 | 标明风险，阻断保存 |
| 时间冲突 | 查询实际可用时段；建议替代时间；硬性变更待确认 |
| 重复提交 | 同请求、同素材、同内容，数据库中始终只有一份草稿 |
| 保存失败 | 输出真实失败，数据库无新增草稿，不宣称成功 |
| 执行上限 | 无论模型如何选择，最多执行 max_steps 个决策，耗尽为 incomplete |
| 动态决策 | 至少两条真实模型路径体现观察结果影响动作，不能用固定 Mock 证明 |

要求外的设计约定：素材 ID 不存在视为资料不足；候选时段全部占用则阻断并请求新时段；草稿也预留时段，避免多个草稿相互冲突。时间必须带时区并位于整点，统一转为 UTC+08:00 进行唯一性检查。

授权边界：调用方是可信 CLI 操作者，`approved_slots` 表示外部已收到的明确确认。本项目没有用户认证系统，不允许模型传入或改变该字段。
