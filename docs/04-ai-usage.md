# AI 使用范围、个人贡献与验证结果

## AI 使用范围

本项目使用 Codex 辅助开发，并使用 DeepSeek `deepseek-flash` 作为项目运行时的决策模型。两者职责不同：Codex 参与实现与验证，DeepSeek 在程序运行时根据实际工具返回选择下一步动作。

开发阶段，Codex 参与需求拆解、方案设计、代码编写、测试设计与执行、文档整理、问题修复和 GitHub 提交，具体包括：

- 将题目要求整理为正常排期、信息缺失、规则风险、时段冲突、重复提交、保存失败六个必验场景。
- 实现 Python CLI、JSON 动作协议、有限步决策循环、素材读取与补查、规则检查、时段查询和 SQLite 草稿保存。
- 实现审核门禁、硬性时间变更待确认、真实保存回执校验、事务内冲突复查及防重约束。
- 编写并运行自动测试，生成离线和真实模型的输入、实际输出、Trace 与评估汇总。
- 根据测试和考核复核修复问题，整理需求、方案、评估与复盘文档。

运行阶段，DeepSeek 每轮接收原始排期请求和此前的工具记录，选择一个动作；本地程序校验动作、执行工具，再将实际结果交给模型。模型不能直接操作数据库，也没有真实发布接口。业务资料使用合成数据，工具使用本地函数，不声称接入真实内容平台。

## 个人贡献与当前边界

本人提供了考核规则和第一题题目，要求实现过程遵循规则；提供了目标 GitHub 仓库、模型服务地址、模型名称及访问配置，使真实模型验证和仓库交付能够完成。交付后，本人进一步要求逐项复核考核要求，并询问仓库结构、运行方式和需要人工补充的材料。

这些贡献主要属于需求输入、运行资源提供和复核要求的提出。具体代码、测试、修复及工具执行由 Codex 完成，不将 AI 生成或执行的工作表述为本人独立编写、亲自发现问题或手工完成测试。

截至本说明形成时，本人尚未提供独立代码修改或独立运行验证的记录，因此个人代码修改记录为“暂无”。后续如亲自修改或验证，应补充实际修改文件、修改原因、执行命令和观察结果，并同步更新相关材料。本说明不替代本人对代码的理解与现场解释。

## 实际修改过程

以下修改由 Codex 在协作中完成，不计作本人独立修改：

| 问题或目标 | 修改与验证 |
|---|---|
| 防止模型绕过审核或虚报成功 | 将审核与时段门禁放到工具层；未获得保存回执不能成功结束；通过越权及虚报成功测试 |
| 重复提交与查询后的时段竞争 | 使用业务幂等键、请求指纹、事务与唯一约束；保存前再次检查冲突 |
| 系统临时目录不可写 | 改用项目 work/ 下的隔离测试目录，重新运行测试 |
| Windows 管道输出编码错误 | CLI 显式采用 UTF-8，增加真实子进程 JSON 解码测试 |
| 补查改写先前的 Trace 内容 | 保存工具结果的深拷贝，验证补查前无 owner、补查后有 owner，并重新生成证据 |
| 重复示例的会话隔离不足 | 首次运行后关闭连接，新建工具会话再次提交，核对同一草稿 ID |
| 时区转换后的整点判断 | 先转换为 UTC+08:00 再检查整点，增加时区边界测试 |
| README 对确认能力描述过度 | 明确首次请求可携带外部已取得的确认，已有草稿的完整确认、更新和撤销流程未实现 |

## 验证方式与实际结果

以下验证由 Codex 在本项目环境中执行，结果保存在仓库中，不表述为本人亲自执行：

1. **自动测试：25 项通过。** 见 [测试报告](../examples/test-results.txt)。覆盖六个必验场景，以及审核保护、虚报成功、执行上限、跨会话防重、时区、Trace 快照和 CLI 编码。
2. **离线场景：10 组达到预期。** 见 [离线评估汇总](../examples/evaluation-summary.json)。输入、实际输出和 Trace 位于 examples/。Mock 是固定策略，只证明流程与工具行为。
3. **真实模型场景：10 组达到预期。** 使用 DeepSeek `deepseek-flash`，见 [真实模型评估汇总](../examples/live/evaluation-summary.json)。输入、输出和 Trace 位于 examples/live/，包含模型返回的请求标识与用量，不保存模型内部思维过程。
4. **动态决策有实际记录。** 信息不足时选择补查或结束，冲突时选择替代时段并保留待确认，保存失败后返回失败。首次冲突场景保留了模型提前结束被拒绝后改为保存的 [错误纠正记录](../examples/live/initial-conflict-recovery.output.json)。
5. **独立导出验证通过。** 从 Git 提交导出的压缩包解压到隔离目录后，自动测试与证据检查通过；私有模型配置及运行数据库未进入导出包。

在项目根目录可执行以下命令复核：

```powershell
python -m unittest discover -s tests -v
python examples/verify_evidence.py
python examples/run_examples.py
```

真实模型重新执行需要本地模型配置：

```powershell
python examples/run_examples.py --model compatible --config work/model-config.json
```

运行脚本会更新对应证据文件；真实模型调用会使用服务额度。密钥仅从环境变量或明确指定的本地私有配置读取，不写入源码、文档、Trace 或提交示例。

## 验证边界

现有结果说明核心链路在这些合成场景下达到预期，不等于生产级合规审核或模型稳定性保证。规则使用示例禁词、必填字段和版权状态，时间槽为每渠道整点一小时，已有草稿的确认、更新和撤销生命周期尚未实现。具体限制见 [评估文档](03-evaluation.md) 和 [考核逐条复核](06-compliance-audit.md)。
